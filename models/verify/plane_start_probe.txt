Where a plane may start. ViZDoom 1.3.2 (ZDoom 2.8.1), mover speed 150,000. Measured for the plane-start miscompile.

1. The clamp (ACS: Floor_MoveToValue / Ceiling_MoveToValue from height 0, floor sectors have ceiling 16,000, ceiling
   sectors have floor -15,000; the height read 8 tics later):
   floor  target 15,999 16,000 16,001 17,000 -12,000 -14,018 -16,000 -16,767 -16,768 -20,000
          reads  15,999 16,000 16,000 16,000 -12,000 -14,018 -16,000 -16,767 -16,768 -20,000
   ceil   target -14,999 -15,000 -15,001 -16,000 12,000 17,766 17,767 17,768 20,000
          reads  -14,999 -15,000 -15,000 -15,000 12,000 17,766 17,767 17,768 20,000
   A floor stops at its sector's ceiling (16,000), a ceiling at its sector's floor (-15,000).

2. One-way MLP plane, check bypassed (doomformer.planes machinery, MLP([[[255]*4],[[-255]]],[[b],[0]],[[10,20,30,40],[100]],
   signed_input=False), x = [45]*4, 3 passes; the twin plane -h1_0 starts at -b and only lowers):
   b       twin start   pass 0   pass 1 and 2 (DOOM vs reference of -h1_0)
   -15,999 15,999       exact    exact
   -16,000 16,000       exact    exact
   -16,001 16,001       exact    11,920 != 11,921
   -16,010 16,010       exact    11,920 != 11,930
   -17,000 17,000       exact    11,920 != 12,920
   opt 0, 1, 2 the same; opt 3 exact (one MoveToValue per plane from the light, no clamp in its path).
   The first pass is exact because the map is built at the start height (floor 16,001 under ceiling 16,000); the reset
   script's Floor_MoveToValue stops at 16,000.

3. Low starts. A floor that only rises, start -S, check bypassed or legal (final twin -12,000 .. 12,000):
   starts from -16,000 down to -20,000 and -28,320 (final -12,000): exact on 3 passes;
   n_in = 41, W = -255, final 12,000, start -29,820: DOOM -h1_0 4,605 != 12,000 (opt 0, pass 1), opt 3 y0 -255 != 0;
   n_in = 36, start -24,720, final 12,000: exact.
   The reset lowers the plane from the previous pass's final value F to the start S in steps of 18,750 units. The third
   step of one move (start below about -25,500) goes wrong:
   Floor_MoveToValue from  12,000: targets -25,501 -25,510 -25,600 exact; -25,800 -26,000 -27,000 read 30,394
   from   8,000: -29,500 -29,600 exact; -29,700 -31,000 read 26,394
   from -12,000: -30,750 -30,751 exact; -31,000 -32,000 read 6,394
   Because F is any earlier input's final value (up to 12,000), a floor start below F - 37,500 = -25,500 can break.
   Floors are exact down to -25,500; the compiler's bound uses -15,000 (the ceiling clamp, below) for floors and
   ceilings alike.
